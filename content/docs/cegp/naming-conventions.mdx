## Descriptive names [#start-with-meaning]

Compare `motor1` with `leftDriveMotor`. The second name tells a teammate where the motor is and what it does. Clear names reduce the number of comments needed to understand an OpMode.

Use the same words throughout the project. If the team calls a mechanism an “arm,” avoid switching between `arm`, `lift`, and `elevator` unless they are different things.

## Java and Kotlin conventions [#common-java-and-kotlin-patterns]

| What you name | Pattern | Example |
| --- | --- | --- |
| Class or interface | `UpperCamelCase` | `ArmController` |
| Variable or method | `lowerCamelCase` | `targetAngleDegrees`, `moveArm()` |
| Constant | `UPPER_SNAKE_CASE` | `MAX_ARM_POWER` |
| Package | Lowercase words | `org.firstinspires.ftc.teamcode.arm` |

These patterns match normal Java style and work well for Kotlin too. Consistency matters more than inventing a special name for every case.

## Measurement units [#put-units-in-measurement-names]

`targetPosition` leaves an important question: is it degrees, encoder ticks, or millimeters? A name such as `targetAngleDegrees` or `targetTicks` answers it.

```java
double targetAngleDegrees = 45.0;
int armEncoderTicks = armMotor.getCurrentPosition();
double maxArmPower = 0.25;
```

These lines are illustrative values inside a larger OpMode. They do not convert ticks to degrees; that conversion needs a measured encoder scale and a known zero position.

## Hardware names [#hardware-names-must-match-configuration]

The name passed to `hardwareMap.get` is a string from the **active Robot Controller configuration**. It is not automatically created by your Java or Kotlin variable name:

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
DcMotor leftDriveMotor = hardwareMap.get(DcMotor.class, "left_drive");
```

</Tab>
<Tab value="Kotlin">

```kotlin
val leftDriveMotor = hardwareMap.get(DcMotor::class.java, "left_drive")
```

</Tab>
</Tabs>

Here, `leftDriveMotor` is a code variable and `left_drive` is the configured device name. The latter must match exactly, including capitalization.

## Naming checklist [#a-quick-naming-check]

Before committing, ask a teammate to read one method without your explanation. If a name makes them ask “which motor?” or “what unit?”, improve that name. Do not rename a configured hardware string without also updating the robot configuration.
