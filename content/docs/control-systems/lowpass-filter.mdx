# Smooth a noisy sensor reading

Suppose a distance sensor says `10.0`, `9.4`, `10.3`, and `9.7 cm` while the robot is not moving. The target is steady, but the readings wobble. A low-pass filter smooths those quick changes so code can pay more attention to the general trend.

A filter also adds delay. If you smooth too much, the reported value takes longer to catch up when the target really moves. Use it only when noise is causing a real problem, and compare the filtered result with the raw reading.

## What the filter does

An exponential moving average blends the newest reading with the previous filtered value:

```text
filtered = alpha × new reading + (1 - alpha) × previous filtered value
```

`alpha` is between 0 and 1:

- `alpha` close to 1 follows changes quickly and smooths less.
- `alpha` close to 0 smooths more but responds more slowly.

## Step 1: Store the filter's state

The filter must remember its last output. For the first reading, use the reading itself; otherwise a starting value of zero can create a fake jump.

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
private boolean hasReading = false;
private double filteredDistance;
```

</Tab>
<Tab value="Kotlin">

```kotlin
private var hasReading = false
private var filteredDistance = 0.0
```

</Tab>
</Tabs>

## Step 2: Update it every time you read the sensor

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
private double filter(double newDistance, double alpha) {
    if (!hasReading) {
        filteredDistance = newDistance;
        hasReading = true;
    } else {
        filteredDistance = alpha * newDistance
            + (1.0 - alpha) * filteredDistance;
    }
    return filteredDistance;
}
```

</Tab>
<Tab value="Kotlin">

```kotlin
private fun filter(newDistance: Double, alpha: Double): Double {
    if (!hasReading) {
        filteredDistance = newDistance
        hasReading = true
    } else {
        filteredDistance = alpha * newDistance + (1.0 - alpha) * filteredDistance
    }
    return filteredDistance
}
```

</Tab>
</Tabs>

The first call initializes the filter. Each later call combines the new measurement with the last filtered output. Call it with one stream of measurements from one sensor; don't reuse the same state for unrelated signals.

## Step 3: Compare raw and filtered values

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
double rawCm = distanceSensor.getDistance(DistanceUnit.CM);
double smoothCm = filter(rawCm, 0.25);

telemetry.addData("Raw cm", "%.1f", rawCm);
telemetry.addData("Filtered cm", "%.1f", smoothCm);
telemetry.update();
```

</Tab>
<Tab value="Kotlin">

```kotlin
val rawCm = distanceSensor.getDistance(DistanceUnit.CM)
val smoothCm = filter(rawCm, 0.25)

telemetry.addData("Raw cm", "%.1f", rawCm)
telemetry.addData("Filtered cm", "%.1f", smoothCm)
telemetry.update()
```

</Tab>
</Tabs>

`0.25` is an example starting point, not a universally correct setting. Run the sensor without moving the target, then move it deliberately. Reduce `alpha` only if the jitter is troublesome and the added lag is acceptable.

## When it helps—and when it does not

A low-pass filter can help with noisy distance, color, or encoder-derived signals. It does not correct sensor bias, bad calibration, a loose mount, or an incorrect unit conversion. Fix those causes first.

Avoid blindly filtering heading angles around the wrap boundary. For example, averaging `179°` and `-179°` as ordinary numbers gives `0°`, even though the headings are nearly the same. Use angle-aware math for wrapped values.

## Practice

1. Hold a stationary target and record raw readings for a few seconds.
2. Add the filter and show raw and filtered values together.
3. Move the target once. Notice how long the filtered value takes to follow.
4. Try a slightly higher and lower `alpha`. Choose the least smoothing that removes the jitter affecting your decision.

A filter setting is a tradeoff between smoothness and response time. Test it at the same loop rate and sensor conditions where your robot will use it.
