## Start with a command

A **control system** turns a goal into a robot action. For example, pushing a gamepad stick gives the drivetrain a command. Asking an arm to hold a position gives its motor a target.

The first question is: **Does the program measure what actually happened?**

![Open-loop control sends a command to a motor. Closed-loop control also reads a sensor and uses that measurement to adjust the next command.](/guides/control-loop-compare.svg)

## Open loop: command only

Suppose your code sets an arm motor to `0.3` power for half a second. The program has sent a command, but it has not measured the arm's final position. Battery voltage, friction, or an added game piece can change where it stops.

Open-loop control is a good first step for learning motor direction and power. It can also work when exact position is unimportant. Test it at low power before using it on a mechanism.

## Closed loop: command, measure, adjust

Now suppose the arm has an encoder. Your code compares the **target position** with the **measured position** and changes motor power based on the difference. That difference is called the **error**.

| If the arm is… | The controller can… |
| --- | --- |
| Below its target | Move it upward |
| Above its target | Move it downward |
| Near its target | Reduce power or hold position |

Feedback helps a robot correct for changing conditions, but it needs a trustworthy measurement and careful tuning. A sensor reading alone does not make an action accurate.

## Learn in this order

1. [Joystick mapping](./joystick-mapping): turn driver input into motor commands.
2. [PID control](./pid-control): use error to correct a motor or mechanism.
3. [Motion profiling](./motion-profiling): choose smoother target motion.
4. [Low-pass filtering](./lowpass-filter): reduce noise in a measurement.
5. [Kalman filtering](./kalman-filter): combine predictions and measurements when simpler filters are not enough.

You do not need to master every technique at once. Begin with one motor and one measurement; add complexity only after you can observe what the robot is doing.
