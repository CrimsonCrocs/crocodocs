## What is VisionBench?

**VisionBench** is the current name of EOCV-Sim. It runs vision code on your computer using a saved image, video, or webcam as the input. This lets you inspect and tune a pipeline without repeatedly installing robot code.

![A test loop: choose an image, run the pipeline in VisionBench, inspect its output, change one setting, and test again.](/guides/visionbench-loop.svg)

It simulates the vision parts of the FTC SDK; it is **not** a full robot simulator. You still need to test camera exposure, lighting, speed, and robot behavior on the real robot.

## 1. Install it

1. Follow the [official VisionBench download instructions](https://docs.deltacv.org/visionbench/downloading-visionbench). The current release requires **Java 25 or newer**. Check with `java -version` before launching it.
2. Download the file for your operating system from the linked release page.
3. Launch the downloaded JAR. If double-clicking does nothing, open a terminal in the download folder and run `java -jar` followed by the **actual filename** you downloaded.

The Java version needed to **run VisionBench on your computer** is separate from the Java and Android Gradle settings used to build your FTC Robot Controller app.

## 2. Make a small Java pipeline

For a first test, use a saved photo of a field object. Create a Java workspace through **Workspace → External → Create Gradle Workspace**. Open that folder in VS Code or IntelliJ, then add `PassThroughPipeline.java` under `src/main/java`:

```java
import org.opencv.core.Mat;
import org.openftc.easyopencv.OpenCvPipeline;

public class PassThroughPipeline extends OpenCvPipeline {
    @Override
    public Mat processFrame(Mat input) {
        return input;
    }
}
```

`processFrame` receives one image frame. Returning `input` shows the frame without changing it. Once this works, try the [one-color pipeline lesson](./writing-pipelines).

The [official workspace guide](https://docs.deltacv.org/visionbench/workspaces/vscode-and-intellij) shows the current menu and file locations. If the pipeline does not appear, read the build error in VisionBench and check that the Java filename matches the class name.

## 3. Test and tune

1. Choose an **image input source** and open your test photo.
2. Select **PassThroughPipeline** in the pipeline list. The preview should show the same photo.
3. Change one part of the pipeline, save the file, and compare the new preview with the original.
4. When you add thresholds, expose supported **public, non-final Java fields** to adjust them in the [variable tuner](https://docs.deltacv.org/eocv-sim/features/variable-tuner-1). Record the values you choose in your code.

Use several photos, including different lighting and object positions. A color range that works on one image may fail on another.

## Using an existing robot pipeline

VisionBench can load a folder of pipeline classes from an Android Studio project, but those classes should not depend on motor or other unsupported robot hardware APIs. Follow its [Android Studio workspace guide](https://docs.deltacv.org/visionbench/workspaces/android-studio) to select only the vision package.

Java workspaces are the simplest supported route. The [pipeline guide](https://docs.deltacv.org/visionbench/introduction/pipelines/how-it-works) says Kotlin and other JVM languages require building VisionBench from source, so do not expect a `.kt` file placed in a Java workspace to appear automatically.

## Next step

After the computer test works, move the pipeline into your FTC project, connect it to [EasyOpenCV on the robot](./easyopencv-basics), and test with the robot's camera. Keep your first robot test slow and simple.
