# When should you use EasyOpenCV?

The FTC SDK already includes **EasyOpenCV** for supported SDK versions (SDK 8.2 and later). For that setup, you do not need to add a separate Maven repository, download a native library, or copy a `.so` file to the Control Hub. Those instructions appear in older tutorials and are not the normal setup for a current FTC project.

EasyOpenCV gives your OpMode a camera stream and a place to run your own OpenCV code. Choose it when you need a custom pipeline. If the built-in FTC Color Locator or AprilTag processor already answers your question, begin with [VisionPortal](../visionportal/vision-portal); it has fewer moving parts.

## What happens when the camera runs?

1. Your OpMode finds a camera by the name in Robot Configuration.
2. EasyOpenCV opens that camera asynchronously. “Asynchronously” means the open result arrives later in a callback, so the robot loop does not wait for the camera to open.
3. You attach an `OpenCvPipeline` before starting the stream.
4. EasyOpenCV passes each camera frame to the pipeline's `processFrame` method.
5. When the OpMode ends, stop the stream and close the camera.

*Source photo: [AndyMark BIOBUZZ scoring elements](https://andymark.com/products/biobuzz-scoring-elements). The mask is a learning example; tune your pipeline against your live camera image.*

The vision illustration shows the stages after a frame reaches your pipeline. EasyOpenCV itself manages camera frames and pipeline calls; it does not choose what object to detect. Your OpenCV code does that.

## Step 1: Configure a webcam

In the Robot Controller configuration, add the webcam and give it a simple name such as `Webcam 1`. That name is part of your program's hardware configuration. If your code asks for `Webcam 1` but the configured device is named `Front Camera`, `hardwareMap` cannot find it.

Connect the camera to the Control Hub or Robot Controller device, then use a preview sample to confirm that the image is live and correctly rotated before you write detection logic.

## Step 2: Find the camera and attach a pipeline

This short setup is the part that belongs in your `LinearOpMode`. `PreviewPipeline` is the small custom class you will build in [Writing Pipelines](./writing-pipelines).

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
int monitorViewId = hardwareMap.appContext.getResources().getIdentifier(
    "cameraMonitorViewId", "id", hardwareMap.appContext.getPackageName());

WebcamName cameraName = hardwareMap.get(WebcamName.class, "Webcam 1");
OpenCvCamera camera = OpenCvCameraFactory.getInstance()
    .createWebcam(cameraName, monitorViewId);
camera.setPipeline(new PreviewPipeline());
```

</Tab>
<Tab value="Kotlin">

```kotlin
val monitorViewId = hardwareMap.appContext.resources.getIdentifier(
    "cameraMonitorViewId", "id", hardwareMap.appContext.packageName
)

val cameraName = hardwareMap.get(WebcamName::class.java, "Webcam 1")
val camera = OpenCvCameraFactory.getInstance()
    .createWebcam(cameraName, monitorViewId)
camera.setPipeline(PreviewPipeline())
```

</Tab>
</Tabs>

The first lines find the preview container used by the Driver Station. The `hardwareMap.get(...)` line connects your Java variable to the named camera. `setPipeline(...)` tells EasyOpenCV which class should process the images.

Use the `OpenCvCameraFactory` and callback signatures from the sample bundled with your installed FTC SDK. EasyOpenCV and SDK APIs have changed over time; the SDK sample is the version-matched reference.

## Step 3: Open asynchronously and handle both outcomes

Opening a camera can take time or fail. EasyOpenCV reports success in `onOpened()` and failure in `onError()`. Start streaming only after success:

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
camera.openCameraDeviceAsync(new OpenCvCamera.AsyncCameraOpenListener() {
    @Override
    public void onOpened() {
        camera.startStreaming(640, 480, OpenCvCameraRotation.UPRIGHT);
    }

    @Override
    public void onError(int errorCode) {
        // Save the error for telemetry in the OpMode loop.
        cameraError = "Camera open failed: " + errorCode;
    }
});
```

</Tab>
<Tab value="Kotlin">

```kotlin
camera.openCameraDeviceAsync(object : OpenCvCamera.AsyncCameraOpenListener {
    override fun onOpened() {
        camera.startStreaming(640, 480, OpenCvCameraRotation.UPRIGHT)
    }

    override fun onError(errorCode: Int) {
        // Save the error for telemetry in the OpMode loop.
        cameraError = "Camera open failed: $errorCode"
    }
})
```

</Tab>
</Tabs>

The `640 × 480` size and `UPRIGHT` rotation are examples, not universal settings. Start with a resolution supported by your camera; more pixels can take more processing time. Do not try to start streaming inside the OpMode before `onOpened()` runs.

## Step 4: Keep the OpMode alive, then clean up

After starting the stream, the OpMode must continue running while you read pipeline results. Keep the result visible in telemetry during the first test. When the OpMode stops, stop streaming and close the device according to the SDK-matched EasyOpenCV sample.

Do not run a drivetrain based on an untested camera result. First confirm the preview, then confirm that the pipeline result changes as you move a target in front of the camera.

## A note about pixel channel order

EasyOpenCV supplies pipeline frames in **RGBA** order. Some desktop OpenCV examples use BGR instead. When converting a frame to HSV, use the conversion code that matches the frame you actually receive, such as `COLOR_RGBA2HSV`; copying `COLOR_BGR2HSV` from a desktop tutorial can produce incorrect colors.

You will apply that conversion one step at a time in [Writing Pipelines](./writing-pipelines).

## If the camera does not open

- Confirm that the configured camera name exactly matches the name in `hardwareMap.get(...)`.
- Check the cable, adapter, and USB connection.
- Confirm that the camera is not already in use by another OpMode or process.
- Read `onError` telemetry and the Robot Controller log.
- Try the version-matched FTC/EasyOpenCV sample before changing resolution or adding image processing.
