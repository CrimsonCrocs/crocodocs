## Computer vision [#what-computer-vision-does]

Computer vision turns camera images into information a robot program can use, such as a detected tag ID, a color region, or an estimated pose. Results depend on camera calibration, lighting, image quality, processing load, and how the robot uses the measurements.

## FTC vision options

### VisionPortal

VisionPortal is the FTC SDK camera and processor interface. It manages camera selection, initialization, previews, and processors. Current SDK resources document AprilTag processing and the FTC color processors for color sensing and blob location. Use the SDK sample OpModes and current FTC Docs for APIs matching your installed SDK.

### EasyOpenCV

EasyOpenCV is a community library built around OpenCV. It is useful when a team needs custom image processing or an existing OpenCV pipeline. It is not the same API as VisionPortal, and the two should not be mixed without following the integration guidance for the libraries involved.

## Workflow [#a-practical-workflow]

1. Choose the simplest processor that answers the robot's actual question.
2. Test camera access and image quality before writing detection logic.
3. Validate detections under the lighting and distances the robot will encounter.
4. Check confidence, visibility, calibration, and stale results before acting on a measurement.
5. Test processor load and control-loop timing on the Robot Controller.

AprilTag IDs, cluster layouts, and scoring elements can be season-specific. Do not hardcode an old season's IDs or colors into a current robot without checking the current Competition Manual and FTC SDK tag library.
