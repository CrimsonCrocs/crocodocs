## What the camera does

A webcam sends images to the Robot Controller. A vision program can then look for a color, shape, or AprilTag in those images. The camera alone does not tell the robot where to drive; your code must interpret what it sees.

![A webcam sends frames through USB to the Robot Controller, where a vision processor turns image pixels into a result for the OpMode.](/guides/webcam-signal-flow.svg)

## 1. Choose a camera

For a Control Hub, choose a **USB Video Class (UVC)** compatible webcam. FIRST lists **Logitech C270, C310, and C920** among cameras it has tested and calibrated. Its [webcam reference](https://ftc-docs.firstinspires.org/en/latest/apriltag/vision_portal/visionportal_webcams/visionportal-webcams.html) includes supported resolutions, frame rates, and field of view.

Start with a camera your team already owns if it appears on that list. More pixels are not automatically better: a higher resolution can add processing work, and a wider view makes a distant target smaller in the image. Check what your vision task needs before buying or changing cameras.

## 2. Mount it for the task

- Aim it at the part of the field you need to observe. Test that a target stays in view while the robot turns and approaches it.
- Keep the camera and USB cable firmly attached. A moving camera changes the relationship between image position and robot position.
- Keep the lens clear of mechanisms. Avoid placing it where a game piece can hit it.
- For distance or pose estimates, measure the camera's position and direction relative to the robot after mounting it. Recheck those measurements whenever you move the camera.

For color detection, test under the lighting you expect at an event. For AprilTag pose, also follow the [AprilTag guide](../visionportal/apriltag-detection) for camera calibration and coordinate conventions.

## 3. Add the webcam to the robot configuration

1. Connect the webcam to the Control Hub's USB port, or to a supported powered USB hub when your setup needs one.
2. In the Robot Controller configuration, add the webcam as a USB device and save the configuration. FIRST's [external webcam configuration guide](https://ftc-docs.firstinspires.org/en/latest/hardware_and_software_configuration/configuring/configuring_external_webcam/configuring-external-webcam.html) shows the screens.
3. Give it a clear name, such as `Webcam 1`. Your code must use **that exact name** when it looks up the camera.

## 4. Run one camera test

Use a webcam sample OpMode included with the [FTC SDK](https://github.com/FIRST-Tech-Challenge/FtcRobotController) or follow the [VisionPortal setup guide](../visionportal/vision-portal). Confirm that the preview shows a live image before adding detection logic.

| If you see… | Check this first |
| --- | --- |
| Camera not found | The USB connection, active robot configuration, and camera name in code |
| Black or frozen preview | Another OpMode using the camera, USB power, and whether the camera opened successfully |
| Detection misses a visible target | Focus, exposure, lighting, resolution, and the processor's settings |
| Slow robot loop | Camera resolution and how much work the vision processor does per frame |

Change one thing at a time and test again. That makes it easier to tell which change helped.
