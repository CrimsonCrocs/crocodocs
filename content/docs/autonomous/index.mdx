## Overview [#what-is-autonomous]

An autonomous OpMode runs without driver input for the **30-second AUTO period** of an FTC match. It can read sensors, move mechanisms, and make decisions based on its program. The exact game tasks and scoring change each season; see the [current season guide](../season-breakdown) and current Competition Manual for those details.

Build an autonomous routine that repeats reliably, stops safely, and handles errors in localization and game-piece interaction. Adding steps can reduce reliability if each step is not tested.

## Core concepts

- **Motion planning** describes where and how the robot should move.
- **Localization** estimates the robot's pose using encoders, an IMU, odometry, or vision.
- **Control** uses sensor feedback to reduce the difference between the desired and measured behavior.
- **Decision logic** handles alternate outcomes, such as a missed game piece or a tag that was not detected.

These components affect each other. A path follower cannot compensate for a badly calibrated localizer, and an AprilTag pose is an estimate whose quality depends on visibility and camera calibration.

## Learning order [#a-reliable-build-up]

1. Test individual hardware safely.
2. Make one short movement and verify motor direction, encoder direction, and stopping behavior.
3. Measure localization error before adding long paths.
4. Add one mechanism action and confirm its timing.
5. Test repeated runs from the real starting position, with realistic battery and field conditions.
6. Add fallback behavior and an explicit safe stop.
