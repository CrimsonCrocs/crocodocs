## What Sloth does

[Sloth](https://github.com/Dairy-Foundation/Sloth) is a Dairy Foundation tool for sending TeamCode changes to an FTC robot through a hot reload workflow. It uses the Sinister runtime and can work with libraries that provide compatible integrations.

Hot reload is useful during development, but it is not equivalent to rebuilding and installing the complete robot app. Its speed depends on the project, network, change, and robot; no fixed upload time is guaranteed.

## Important limits

The Sloth project documents that hot reload is limited to eligible classes in the TeamCode package. Changes to dependencies, SDK code, or other non-reloaded files need a full install. Some changes may compile but still not take effect correctly when hot reloaded. Follow the current repository instructions and perform a full install whenever a change falls outside the supported hot-reload scope.

<Callout type="warn" title="Do a full install when in doubt">
Do not rely on a hot reload to deploy a new library, SDK, or build configuration. Confirm that the code running on the Control Hub matches the code you intend to test.
</Callout>

## Installation

Sloth setup has changed across releases and depends on the FTC SDK and whether the project uses other Dairy libraries. Follow the current [Sloth README](https://github.com/Dairy-Foundation/Sloth) and [Dairy Templates](https://github.com/Dairy-Foundation/Templates) rather than copying old plugin versions from this page. In particular, set up the currently documented Load plugin and deployment tasks exactly as the README describes.

FTC Dashboard and Panels integrations use Sloth-compatible artifacts. Their versions must match the current Sloth release and dashboard version; the official README has the compatible coordinates. Do not combine an ordinary dashboard dependency and a Sloth-compatible replacement unless its instructions explicitly call for it.

## Development workflow

1. Complete the official initial install and confirm the OpMode runs.
2. Make one small change within the documented reload scope.
3. End the OpMode and use the current Sloth deployment task.
4. Confirm the changed behavior on the robot.
5. Use a full install after dependency, SDK, or other non-reloadable changes.

Keep a standard full-install path available and test it before competition. Hot reload is a development convenience, not a substitute for a known-good deploy process.

## Deploy a TeamCode change

Sloth has no Java API to call from an OpMode. You use its Gradle task after adding the Load plugin and completing one normal install. With an Android Studio project that has the current Sloth task configured, the deploy command is:

```powershell
./gradlew.bat :TeamCode:deploySloth
```

The Control Hub must already be connected to the computer over USB or ADB Wi-Fi. In Android Studio, select the robot project and run the task after ending the active OpMode. A small edit to a class under `org.firstinspires.ftc.teamcode` can then be loaded without installing the full Robot Controller app again.

Use a normal `TeamCode` install after changing Gradle files, adding or updating a library, or changing anything outside the hot-reloaded package. The exact plugin setup and task names depend on the Sloth release and project template, so follow the current [Sloth README](https://github.com/Dairy-Foundation/Sloth) before adding the task to your project.
